# Email bridge experiment (Stalwart mailbox first)

The primary architecture is now Stalwart for the hosted
`me@iniyanjoseph.com` mailbox, with Matrimail connecting to that mailbox
for Cinny. See [`../mail-server/README.md`](../mail-server/README.md).
Forwarding from Gmail/Outlook happens at those providers; their IMAP accounts
are not bridged directly in the initial deployment.

This repository stages [Matrimail](https://github.com/Leicas/matrimail)
(revision `6f22bb7115063241eb91d146ad1f177a56ae3ad5`, upstream
v1.9.3). It is a third-party experimental project, **not** a standard
supported NixOS/mautrix package.

**Do not enable** `contabo.emailBridge.enable` until the integration and
registration are verified. It defaults to `false`. Merely deploying the
current flake will create an isolated system user/directory but will **not**
start a bridge, restart Synapse for an additional appservice, send email,
or access Gmail.

## Reality check

- Matrimail claims IMAP reception, one Matrix room per email thread,
  attachments, replies, and composition.
- Hosted Stalwart: login to the local IMAP/SMTP mailbox only; ensure
  `me@iniyanjoseph.com` exists before Matrimail account setup.
- Gmail: app-password login may work after 2-Step Verification; upstream
  also describes a Gmail OAuth transport, but the account authorization
  flow must be verified before relying on it.
- Outlook.com and Microsoft 365: **OAuth2 is required** for IMAP and SMTP.
  The upstream README's Microsoft "app password" guidance is outdated.
  Do not supply a Microsoft account password to this bridge.
- Cinny support for creating new emails and encrypted email rooms is untested.
- Reply-all, changing CC/BCC, drafts, scheduled/delayed send, moving mail,
  spam controls, complete historical backfill, and multi-account behavior
  have **not** been verified. Do not assume Thunderbird-equivalent features.
- The upstream Go bridge links against legacy libolm for E2EE. The
  insecure-package exception is scoped ONLY to the optional Nix development
  shell. There is no system-wide insecure-package allowance here.
- Every email thread maps to a separate Matrix room, which may produce a
  large number of rooms on a full inbox. For the first trial, use one
  low-volume account or dedicated Gmail label.

## A. Build without deploying (Contabo)

From Fish in the repo on Contabo:

```fish
cd /etc/nixos
# Applies staging only: no bridge service or Synapse registration.
sudo git pull --ff-only
sudo nixos-rebuild build --flake ./hosts/contabo#contabo

# Builds a pinned source revision into ~/.local/share/matrimail-build/.
bash hosts/contabo/email-bridge/build.sh
```

The source build requires network access to GitHub and Go dependencies. It
has not yet been tested on Contabo; investigate build failures before
continuing. The pinned `go`, `olm` and C toolchain come from this host's
NixOS flake. No `nixos-rebuild switch` is needed to compile.

## B. Prepare the bridge, then enable it (NOT YET VALIDATED)

Before enabling, the following must be established:

1. Provision `/var/lib/matrimail/bin/matrimail` with the built binary,
   and `/var/lib/matrimail/config.yaml` generated by the bridge CLI
   (`--generate-example-config`). Use the standalone **HTTP appservice**
   configuration, local Synapse URL `http://127.0.0.1:8008`,
   homeserver domain `iniyanjoseph.com`, bind to
   `127.0.0.1:29319`, and SQLite URI
   `file:/var/lib/matrimail/matrimail.db?_fk=1`.
2. Use Matrimail's `--generate-registration` CLI, pointed at that config,
   to create `/var/lib/matrimail/registration.yaml`. It must match the
   config's appservice ID, URL and tokens.
3. Ensure generated config, SQLite database and registration are owned by
   `matrimail:matrimail` and the registration is readable by the Synapse
   systemd service's supplementary `matrimail` group; never make tokens
   world-readable.
4. Create a root-only environment file
   `/var/lib/secrets/matrimail.env` containing a strong, stable
   `MATRIMAIL_PASSPHRASE`; losing it may prevent decryption of email
   credentials. Never put credentials in Nix/Git/the Nix store.
5. After configuration is verified, change
   `contabo.emailBridge.enable = true;` in
   `hosts/contabo/configuration.nix`, run a NixOS build, then switch.
   The Synapse restart requires a readable valid registration file.
6. Only after the bridge is online, DM its bot in Cinny and use
   `!matrimail login`. Follow a guided account-login flow; do **not**
   send an app password inline in a persistent Matrix command message.
   Verify that commands and credentials are protected appropriately.
7. First test: receive an email, reply, compose, attach a file, and check
   a threaded conversation in both Gmail and Matrix. Verify accidental
   multiple sends do not occur. **Do not** start with bulk historical sync.

## C. Status commands after opt-in activation

```fish
systemctl is-active matrimail
sudo journalctl -u matrimail -n 80 --no-pager
```

When disabled (current state), there is no running `matrimail` unit.

## D. Backups and credentials

Before enabling in production, include `/var/lib/matrimail` in the
encrypted Restic backup paths and restore-test it. Keep the registration,
database, credentials, and generated passphrase private. Disabling the
service will not delete its stored data.

**No public SMTP ports or mail DNS changes are needed**: this is a client
of existing Gmail/Outlook accounts, unlike Postmoogle.
