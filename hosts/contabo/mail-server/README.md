# Stalwart + Matrimail — Contabo cutover plan

## Current status: STAGED; NO LIVE CHANGE

This directory accompanies `../mail.nix` and `../email.nix`.
The only committed changes are NixOS source files. Neither the mail
server nor Matrimail is enabled:

```nix
contabo.mail.enable = false;
contabo.emailBridge.enable = false;
```

Do **not** run `nixos-rebuild switch` while the Discord history collector
is running. Staging is safe in Git; a switch can restart services and
interrupt collection. The staged mail module has not been evaluated
against the live flake or tested on the Contabo host yet.

### Intended result

- `me@iniyanjoseph.com` is a normal, hosted Stalwart mailbox.
- Thunderbird accesses that mailbox via IMAPS and SMTP submission.
- Matrimail connects to that same mailbox over IMAP/SMTP and exposes
  email conversations in Cinny. Its threading, reply, and Sent sync
  must be verified in practice; full read-state/delete synchronization
  with Matrix is **not** promised.
- Gmail/Outlook forward *new* incoming mail to the hosted address once
  forwarding has been verified. A reply sends as
  `me@iniyanjoseph.com`, not the original destination address.
- Gmail/Outlook old messages and state are **not** migrated/synchronized
  by forwarding.

There is no Postmoogle.

## 1. Preflight (READ-ONLY; may run before the Discord job is done)

On Contabo, in Fish, after pulling the repository:

```fish
cd /etc/nixos
bash hosts/contabo/mail-server/preflight.sh
```

Preflight reports MX, A, AAAA, PTR, active listeners, and free space,
and explicitly *does not* change DNS or email configuration.

Before cutover, confirm:

- The Contabo IP can receive external TCP/25. Test from another machine
  when the mail daemon is listening; testing localhost is insufficient.
- In Contabo's panel, IPv4 PTR / reverse DNS for `213.199.55.255`
  is `mail.iniyanjoseph.com`. If advertising IPv6, configure its PTR
  and outbound reputation too. Otherwise do not publish `mail` AAAA.
- Existing Cloudflare MX and Email Routing records have been reviewed.
  Replacing them too soon can break mail currently used at this domain.
- An SMTP relay is configured if direct sending fails or receives poor
  deliverability (the current module does **not** preconfigure a relay).
- There is enough disk space for messages, attachment copies, search
  indexes, and backup staging, beyond existing Nextcloud/Matrix usage.

## 2. DNS records (ONLY after services are tested)

In Cloudflare DNS for `iniyanjoseph.com`:

| Type | Name | Value | Comment |
|---|---|---|---|
| A | mail | 213.199.55.255 | DNS only, **not proxied** |
| MX | @ | mail.iniyanjoseph.com priority 10 | **Do not add/change until cutover** |
| TXT | @ | v=spf1 mx -all | Replace with policy including outbound relay if used; never create multiple SPF TXT records |
| TXT | _dmarc | v=DMARC1; p=none | Starting policy only; tighten after testing |
| TXT | selector._domainkey | From Stalwart DKIM setup | Actual selector/value must be generated by Stalwart |

Use explicit DNS-only mode for the `mail` A record. Cloudflare HTTP
proxy does not handle SMTP, IMAP or submission.

Do not change MX, SPF, DKIM, or DMARC without auditing existing records,
because `contact@iniyanjoseph.com` and other existing domain mail
addresses may be active.

## 3. Bootstrap credentials (after collector, before switch)

Create the Stalwart fallback admin secret **outside Git/Nix store**:

```fish
sudo sh -c 'umask 077; openssl rand -hex 32 | tr -d "\\n" > /var/lib/secrets/stalwart-admin-password'
sudo stat -c '%a %U:%G %n' /var/lib/secrets/stalwart-admin-password
```

Store the generated value in your password manager using a private
terminal. The file's actual content is the temporary admin password;
do not share it or commit it. Configure a normal scoped administrator
and retire fallback access after provisioning.

## 4. Evaluate and activate (ONLY after Discord collection is done)

```fish
cd /etc/nixos
sudo git pull --ff-only
# To evaluate the disabled, current configuration:
sudo nixos-rebuild build --flake ./hosts/contabo#contabo
```

The build is a preflight, not a switch. It does not prove Stalwart starts.

After checking mail DNS, credentials, and certificate issuance:
edit `configuration.nix` to set `contabo.mail.enable = true;`.
First run `sudo nixos-rebuild build --flake ./hosts/contabo#contabo`,
review the diff, then switch only once the Discord history process
is finished and the Stalwart bootstrap prerequisites are ready.

When enabled, the module declares:

| Interface | Endpoint |
|---|---|
| SMTP inbound | mail.iniyanjoseph.com:25 |
| SMTP submission | mail.iniyanjoseph.com:587 (STARTTLS) |
| SMTP submission TLS | mail.iniyanjoseph.com:465 |
| IMAPS | mail.iniyanjoseph.com:993 |
| Stalwart HTTP backend | 127.0.0.1:8081 (not public) |
| Stalwart admin/JMAP | https://mail.iniyanjoseph.com/ (Nginx reverse proxy) |

Nginx and ACME already own 80/443, so mail does not bind either port.
NixOS issues a new certificate for `mail.iniyanjoseph.com` and
shares its key only with the needed services. Stalwart 0.15.5 is
pinned by this flake and uses TOML settings; do not follow the
newer 0.16.x JSON configuration instructions.

## 5. Create the mailbox in Stalwart

Once the service is healthy and the HTTPS certificate is trusted:

1. Authenticate to the Stalwart WebUI at
   `https://mail.iniyanjoseph.com/admin`.
2. Configure the domain `iniyanjoseph.com` and the actual local mailbox
   `me@iniyanjoseph.com`, with its own unique password.
3. Enable/verify DKIM signing and record the selector's TXT data.
4. Confirm spam filtering, recipient restrictions and SMTP relay
   policy. **Do not operate an open relay.**
5. Test local delivery and authenticated outbound submission with a
   small external test address. Check SPF/DKIM/DMARC, PTR, and whether
   Gmail/Outlook send your outbound email to Spam.
6. Only after that, change MX/forwarding (and never prematurely remove
   your old mail provider). Verify receipts from multiple senders.

Traditional client:

- IMAP server `mail.iniyanjoseph.com`, port `993`, SSL/TLS
- SMTP server `mail.iniyanjoseph.com`, port `587`, STARTTLS
- Username `me@iniyanjoseph.com`; password = Stalwart mailbox password

## 6. Attach Matrimail to the local mailbox (second activation)

Matrimail is staged separately in `../email-bridge`.
It is **not** started automatically by enabling Stalwart.

Test its build with:

```fish
bash hosts/contabo/email-bridge/build.sh
```

Then follow `email-bridge/README.md` to generate the appservice
registration and configure local IMAP/SMTP credentials, without putting
passwords in Git. Only then turn on
`contabo.emailBridge.enable = true;` and switch the NixOS profile.

Initial acceptance tests:
1. Message sent to `me@` arrives in Thunderbird and Cinny.
2. Gmail forward arrives and its original author is visible.
3. Reply via Cinny has From: `me@iniyanjoseph.com` and correct
   `In-Reply-To`/`References` headers.
4. Reply from Thunderbird appears in Stalwart's Sent folder; determine
   whether Matrimail also reflects it into Cinny.
5. Attachments and reply-all function correctly; test duplicates.
6. Reconnect Matrimail and confirm no duplicate messages/rooms.

## 7. Rollback and backups

Backups: when their services are enabled, encrypted Restic includes
`/var/lib/stalwart` and `/var/lib/matrimail` plus existing
`/var/lib/secrets` and ACME keys. Confirm by checking a fresh snapshot
and performing a file-level restore test.

Rollback service configuration via the previous boot generation if needed,
but **DNS rollback is separate**: restore the original MX and SPF records
before switching the primary mail service off. Preserve queued messages
and mailbox data. Forwarders should be left disabled until delivery
has been tested end to end.

Sources: NixOS 26.05 Stalwart module, Stalwart 0.15 sample TOML,
Cloudflare's mail-DNS documentation, and upstream Matrimail README.
